Built by Claude Code (Claude Opus 5.5) from the paper, revised from the group's v1 grades.
Editing a rough cut with a prompt now changes only the part the prompt is about, and the edit's description
says exactly what changed, section by section. Everything else is as in v1; there is still no export of the
final video.

## Changed

- **V-11 · Edit a version with a prompt.** The grades gave no notes, so I am guessing the cause. Before, the
  model rewrote the whole rough cut, so an edit could change sections the prompt was not about, or not shorten
  anything. Now the model names only the sentences to remove or add, and every other sentence stays the same.
  If a "shorten" request does not make the version shorter, VideoDiff asks the model once more, then shows an
  error instead of producing an unchanged copy. The change summary under the edited version ends with the
  measured change, e.g. *[“Making Stock From Scraps” −3 sentences (40s → 26s); other sections unchanged]*.
  Tested once on the pheasant video with "Shorten the part about making stock.": the stock section went from 40 s
  to 26 s, and no other section changed.
- **V-11 · Edited version directly below the original.** Before, an edited version stayed below its original
  only in the default order. Now it stays there when the list is sorted too (as long as both are pinned, or both
  not pinned).

## Assumptions

- Same as v1. Also: an edit is a small change (remove or add sentences), not a fresh rough cut.
