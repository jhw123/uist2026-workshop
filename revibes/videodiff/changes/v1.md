Built by Claude Code (Claude Opus 5.5) from the paper.
All three editing stages (rough cut, B-roll, text effects) work end to end on the two workshop videos: 10
alternatives per stage, compared in an aligned timeline view and transcript view, with sorting, pin/archive,
edit, recombine, Surprise me and regenerate. Model answers come from the bridge's small model, so the quality and
diversity of the alternatives are weaker than GPT-4o's would be, and there is no export of the final video.

## Built

- **Versions outline** (Fig. 2.a): every version of each stage, pinned in blue and archived in grey; click to jump.
- **10 rough cuts** on upload, then **10 B-roll** versions from a chosen rough cut, then **10 text-effect**
  versions from a chosen B-roll version. Each batch uses the Appendix B augmentation prompts (length × focus,
  media × frequency, style × frequency).
- **Video player** per version that plays the kept parts back to back, with B-roll and text effects overlaid.
- **Timeline view** (Fig. 3, 4.b): sections extracted once from the source and coloured the same in every
  version. **Edited / source timeline** toggle, with excluded parts shown lighter. Hover for thumbnails, topic
  keywords and narration (including what an excluded part is missing); click to play from there. B-roll
  thumbnails with search keyword, and text-effect keywords, sit above the timeline.
- **Transcript view** (Fig. 5, 4.c): sections with clickable headings, visually concrete keywords in bold,
  a mini timeline, edited / source transcript toggle, synchronised scrolling across versions, and sentences
  with B-roll or text effects highlighted and clickable.
- **Organizing**: sort by duration and number of sections (rough cut), number of effects and media type
  (B-roll), number of effects and style (text); pin to top, archive to bottom.
- **Customizing** (Fig. 6): edit a version with a prompt (new version appears right below, with a summary of
  the changes); generate new from a prompt; recombine by version number ("#3", "#7"); Surprise me. New
  versions are pinned.
- **Upload video** with a transcript, and **Start over**.

## Assumptions

- Sections: 4–8 consecutive sections per video, each with a title and topic keywords; gaps and overlaps
  are repaired so every sentence belongs to one section.
- Rough cuts are whole transcript sentences. When the model misses the requested length, sentences are
  trimmed or added until it fits (initial batches only; prompts and edits are kept as returned).
- A B-roll covers its whole sentence; a text effect starts at its phrase and lasts to the end of the sentence
  (at least 1.8 s).
- Pinned versions of a stage are kept when a new batch of that stage is generated; unpinned ones are replaced.
- The tenth augmentation combination of each batch is a random pair (the paper's 3 × 3 grid gives 9).

## Substitutions

- **GPT-4o → the workshop LLM bridge** (Claude Code's small model, Haiku): no API keys at the workshop. JSON
  output is used; temperature and model name are ignored.
- **Whisper transcription → the transcripts in `papers/videodiff/materials/`**; uploads need a Whisper JSON
  or SRT file.
- **Stock media API → keyword search over the local B-roll library** (39 items); no match is shown as
  "no result".
- **Remotion → a custom HTML5 player**; **React + d3 → plain JavaScript and CSS** (no build step).
- These are also listed in the app's left panel.
