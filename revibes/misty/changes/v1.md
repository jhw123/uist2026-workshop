Built by Claude Code (Claude Fable 5.1) from the paper.
Misty's node-based canvas, global blending by connecting an example to a source, drag-and-drop blending of a selected region with the Color / Layout / Content / Customize dialog, semantic diff toggles, the live code editor, Regenerate and Fix Render all work, in a live mode (through the LLM bridge) and a cached mode that replays the paper's scenario from recorded responses. Blends are only as good as the bridge's model; small visual details often need the code editor.

## Built
- Infinite canvas (React Flow) with Reference Example nodes (images) and Code Render nodes (live React + Tailwind rendering), minimap and zoom controls.
- Global blending: connect an example's handle to a source node; a new Code Render appears to the right with edges from both parents.
- Localized blending: draw a region on an example (Undo / Done), drag the dashed selection onto a part of a rendered UI; the part under the cursor is highlighted while hovering; on drop, the "Pick Blending Option" dialog offers Color, Layout, Content and Customize (free-text aspect), with Cancel / Next. Several aspects can be chosen together.
- Semantic diff: each blend output has an "Applied Changes" panel listing categorized changes with On / Off toggles, "Reset All", and a chevron to collapse it. Toggling sends another model call that updates the code; the class-level before/after list is shown under each category.
- Live code editor, opening on the right from "Show Code", edits re-render the node.
- "Regenerate" (re-run the same blend) and "Fix Render" (send the render error to the model), plus regex repair rules on every output.
- Upload of screenshots and hand-drawn sketches as examples, bundled sample examples (Health Categories, music profile, store products, a sketch) and sample sources (Fuji's profile, parks list), pasting your own component.
- The paper's Appendix A.3 prompts, verbatim with placeholders filled.
- Two modes: Live (LLM bridge) and Golden path (cached), with a Guide panel listing the scenario's steps, and a fixture recorder for re-recording.

## Assumptions
- Toggling a semantic-diff category updates the same node in place (Figure 1 D shows the panel inside the output node); the scenario figure draws the toggled result as a separate frame.
- The prompt for the toggle call and for Fix Render are not in the paper; ours ask for `{ "updatedCode" }` JSON.
- For drag-and-drop, the model receives the selected region as the reference image and the full screenshot for context, plus the rendered HTML of the drop target, as the paper's prompt implies ("rendered HTML based on the source React code").
- The hover highlight snaps to block elements (not single spans or icons).
- Example nodes can be dragged whole (grip chip) or by a selected region.

## Substitutions
- GPT-4o → the LLM bridge's model. Recorded fixtures and the README use Claude Sonnet (`BRIDGE_MODEL=sonnet`); the bridge's default Haiku also works but produces weaker blends.
- The paper's stock photos → ten photos from picsum.photos in `public/stock/`.
- The paper's example screenshots (Apple apps) → recreated as small HTML pages styled after the figures (`app/examples-src/`, rendered by `scripts/render-examples.sh`) with stock photos in place of product shots, so no annotations from the figures remain; plus one sketch we drew.
- Tailwind is compiled in the browser (`@tailwindcss/browser`) instead of a build step, so generated classes work at runtime.
